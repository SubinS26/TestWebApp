1. EXECUTIVE SUMMARY & PROJECT SCOPE
--------------------------------------------------------------------------------
This project is a scalable, cloud-native video-sharing web application built to
emulate modern platforms like Instagram Reels and TikTok. It features a fully
decoupled architecture with a React-powered frontend, an Express/Node.js REST API,
persistent Azure Database for MySQL Flexible Server, and Azure Blob Storage for
multi-media asset management.

Key Technical Highlights:
  - Architecture: PaaS Cloud-Native model with complete Kubernetes (K8s) alternative.
  - Role-Based Access Control (RBAC): Creator (Influencer) vs Consumer (Follower).
  - Dedicated Video Reel Upload Modal: Real-time high-definition video preview player,
    custom metadata (Title, Publisher, Producer, Genre, Age Rating), emoji picker,
    user tagging, and location tagging (without static photo filters).
  - High-Performance Feed & Explore Gallery: Custom MediaThumbnail component
    supporting both videos (with "▶ Reel" indicator badges) and photos.
  - Cognitive NLP Sentiment Engine: Real-time sentiment analysis intercepting all
    consumer comments before database persistence.
  - Media Processing Pipeline: FFmpeg integration for standardizing and transcoding
    uploaded video files into web-optimized resolutions.
  - Performance & Caching Network: In-memory LRU/TTL caching layer, compound B-tree
    database indexing, and N+1 query elimination (reducing API latency by >70%).
  - Kubernetes (K8s) GitOps Suite: Multi-stage Docker containerization, 3-replica
    Deployment with RollingUpdate, HPA (2-10 pods), PDB, PVC, Ingress, and CI/CD.

SECTION F: Performance Optimizations & Caching Network (7:45 - 9:00)
----------------------------------------------------------------------
[Script / Speech]:
"To guarantee sub-second response times and high scalability under heavy traffic:

1. In-Memory LRU/TTL Caching Network:
   - Implemented in 'config/cache.js'.
   - Frequently requested entities (User profiles, Post counts, Explore feeds)
     are served from memory with automatic invalidation, achieving cache hit times
     under 1ms.

2. Database Indexing:
   - Compound B-tree indexes were created on Azure MySQL (posts, likes, comments,
     followers, bookmarks).

3. Elimination of N+1 Queries:
   - All sequential database loops were refactored into concurrent Promise.all
     resolutions, reducing API latency from 1.21s down to ~0.33s (a 72.5% speedup)."

[Actions to show on screen]:
1. Navigate quickly between Feed, Profile, and Explore to demonstrate instant, lag-free transitions.
2. Open Browser DevTools Network tab to highlight fast TTFB (<250ms).
